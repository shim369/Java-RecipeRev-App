## 1. 画面一覧

URLの `{id}` はレシピID、`{no}` は版番号、`{logId}` は調理ログIDを表す。
版は「レシピIDと版番号」で指定する(例: `/recipes/3/versions/2` = レシピ3の第2版)。DBの内部IDより、URLを見て意味が分かるようにするため。

| 画面ID | 画面名 | URL | 関連機能 | Phase |
|---|---|---|---|---|
| SCR-01 | レシピ一覧 | `GET /recipes`(`/` はここへリダイレクト) | F-01, F-04 | 2 |
| SCR-02 | レシピ新規登録 | `GET /recipes/new` | F-02 | 2 |
| SCR-03 | レシピ詳細 | `GET /recipes/{id}` | F-06, F-10 | 2(版履歴・グラフは3/4) |
| SCR-04 | レシピ基本情報編集 | `GET /recipes/{id}/edit` | F-03 | 2 |
| SCR-05 | 版編集(新しい版の作成) | `GET /recipes/{id}/versions/new?base={no}` | F-05 | 3 |
| SCR-06 | 版詳細 | `GET /recipes/{id}/versions/{no}` | F-06, F-08, F-09 | 3 |
| SCR-07 | 版比較(差分) | `GET /recipes/{id}/diff?from={no}&to={no}` | F-07 | 3 |
| SCR-08 | 調理ログ登録 | `GET /recipes/{id}/versions/{no}/logs/new` | F-09 | 4 |
| SCR-09 | 傾向分析 | `GET /recipes/{id}/analysis` | F-11 | 5 |
| SCR-99 | エラー | (例外発生時) | 共通 | 2 |

## 2. 更新系のURL(フォーム送信の宛先)

更新の後は **PRG(Post/Redirect/Get)パターン** で一覧や詳細の画面へリダイレクトする。ブラウザを再読み込みしたときに同じ登録が二重に行われないようにするため。

| 操作 | メソッド・URL | 処理後に移る画面 |
|---|---|---|
| レシピ登録 | `POST /recipes` | SCR-03 |
| 基本情報更新 | `POST /recipes/{id}` | SCR-03 |
| レシピ削除(論理) | `POST /recipes/{id}/delete` | SCR-01 |
| 新しい版の保存 | `POST /recipes/{id}/versions` | SCR-06(新しい版) |
| 試作を開始 | `POST /recipes/{id}/versions/{no}/start-trial` | SCR-06 |
| この版を決定版にする | `POST /recipes/{id}/versions/{no}/finalize` | SCR-06 |
| 調理ログ登録 | `POST /recipes/{id}/versions/{no}/logs`(multipart) | SCR-06 |
| 調理ログ削除 | `POST /recipes/{id}/logs/{logId}/delete` | SCR-06 |
| 傾向分析を実行 | `POST /recipes/{id}/analysis` | SCR-09 |

> HTMLのフォームは GET と POST しか送れないため、削除も `POST .../delete` にしている(PHPの素朴な実装と同じ考え方)。

## 3. JSON API(画面から JavaScript で呼ぶもの)

| メソッド・URL | 用途 | 返す内容 |
|---|---|---|
| `GET /api/recipes/{id}/rating-trend` | 評価推移グラフ(SCR-03) | `[{ "versionNo": 1, "avgRating": 3.5, "logCount": 2, "status": "TRIAL" }, ...]` |
| `GET /photos/{fileName}` | 調理ログの写真を表示 | 画像ファイル |

## 4. 各画面の詳細

### SCR-01 レシピ一覧
| 区分 | 内容 |
|---|---|
| 表示項目 | レシピ名、説明(先頭50文字)、最新版番号、決定版の版番号(なければ「—」)、全体の平均評価、更新日時 |
| 並び順 | 更新日時が新しい順 |
| 操作 | 「新規登録」→ SCR-02、レシピ名 → SCR-03 |
| 補足 | 論理削除したレシピは表示しない。0件のときは「まだレシピがありません」と表示 |

### SCR-02 レシピ新規登録
| 区分 | 内容 |
|---|---|
| 入力項目 | 名前、説明、材料の行(材料名・分量・単位・メモ)、手順(テキストエリア、1行 = 1手順)、変更メモ |
| 操作 | 「材料を追加」「この行を削除」(JavaScript)、「登録」→ SCR-03、「キャンセル」→ SCR-01 |
| 補足 | 入力エラーのときは同じ画面に戻り、項目ごとにメッセージを表示する。入力した値は残す |

### SCR-03 レシピ詳細
| 区分 | 内容 |
|---|---|
| 表示項目 | レシピ名、説明、**代表版**(決定版があれば決定版、なければ最新版)の材料・手順、版履歴の表(版番号・状態・作成日・変更メモ・平均評価・調理回数)、評価推移グラフ |
| 操作 | 「基本情報を編集」→ SCR-04、「削除」(確認ダイアログあり)→ SCR-01、版番号 → SCR-06、「2つの版を比較」(版履歴でラジオボタン2つを選ぶ)→ SCR-07、「最新版を元に編集」→ SCR-05、「傾向分析」→ SCR-09 |
| 補足 | 状態はバッジで表示(下書き=灰、試作中=青、決定版=金) |

### SCR-04 レシピ基本情報編集
| 区分 | 内容 |
|---|---|
| 入力項目 | 名前、説明 |
| 操作 | 「更新」→ SCR-03、「キャンセル」→ SCR-03 |
| 補足 | 「材料・手順の変更は版の編集から行います」と案内する |

### SCR-05 版編集(新しい版の作成)
| 区分 | 内容 |
|---|---|
| 表示項目 | 派生元の版番号と状態 |
| 入力項目 | 材料の行、手順、変更メモ(最初は派生元の版の内容が入っている) |
| 操作 | 「新しい版として保存」→ SCR-06、「キャンセル」→ 派生元の SCR-06 |
| 補足 | 変更がないまま保存すると「変更がありません」と表示して、この画面に戻る(BR-03) |

### SCR-06 版詳細
| 区分 | 内容 |
|---|---|
| 表示項目 | 版番号、状態、作成日時、派生元の版、変更メモ、材料一覧、手順、この版の調理ログ一覧(調理日・評価・味メモ・写真サムネイル)、平均評価 |
| 操作 | 「この版を元に編集」→ SCR-05、「1つ前の版と比較」→ SCR-07、「試作を開始」(下書きのときだけ)、「この版を決定版にする」(決定版でないときだけ。確認ダイアログで「現在の決定版 第N版は試作中に戻ります」と表示)、「調理ログを登録」→ SCR-08、調理ログの「削除」 |
| 補足 | 状態によって表示するボタンを変える。サーバ側でも状態を確認する(画面を通さず送られたリクエストへの対策) |

### SCR-07 版比較(差分)
| 区分 | 内容 |
|---|---|
| 入力項目 | 比較元の版・比較先の版(セレクトボックス)、「比較」ボタン |
| 表示項目 | 材料の差分表、手順の差分(行ごと)、変更件数のまとめ(追加 n / 削除 n / 変更 n)、両方の版の平均評価 |
| 色 | 追加 = 緑、削除 = 赤、変更 = 黄(「100g → 120g」のように変更前と変更後を並べる) |
| 操作 | 版番号 → SCR-06、「戻る」→ SCR-03 |
| 補足 | 色だけに頼らず「+」「−」「~」の記号も付ける(色が見分けにくい人への配慮) |

### SCR-08 調理ログ登録
| 区分 | 内容 |
|---|---|
| 入力項目 | 調理日(初期値: 今日)、評価(1〜5、ラジオボタンで星を表示)、味メモ、写真(ファイル選択、選んだらプレビュー表示) |
| 操作 | 「登録」→ SCR-06、「キャンセル」→ SCR-06 |
| 補足 | 下書きの版のときは「登録すると試作中になります」と案内する(BR-08) |

### SCR-09 傾向分析
| 区分 | 内容 |
|---|---|
| 表示項目 | 最後に分析した日時、分析に使った版の数、材料ごとの結果表(材料名・単位・相関係数 r・強さ・傾向の文章)、「データ不足」の材料一覧、因果関係ではないという注記 |
| 操作 | 「分析を実行」(POST)、「戻る」→ SCR-03 |
| 補足 | まだ分析していないときは「分析を実行してください」と表示する。Pythonの実行に失敗したときはエラーメッセージを表示する |

### SCR-99 エラー
| 区分 | 内容 |
|---|---|
| 表示項目 | エラーの種類(見つかりません / 不正な操作 / システムエラー)、メッセージ |
| 操作 | 「レシピ一覧へ」→ SCR-01 |

## 5. 共通レイアウト
- ヘッダー: アプリ名「RecipeRev」(→ SCR-01)、パンくずリスト(例: レシピ一覧 > カレー > 第3版)
- フラッシュメッセージ: 更新が成功したときに画面上部へ表示する(例: 「第4版を作成しました」「第3版を決定版にしました(第2版は試作中に戻りました)」)
- Thymeleaf の layout(fragment)でヘッダーとフッターを共通化する
